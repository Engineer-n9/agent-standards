# Planning Package Review

Review candidate packages without activating work, changing project state, or editing implementation files.

## Required reading

Read the consumer operating manual, local overlay, project-state/memory authorities if used, every candidate artifact, current code at proposed change surfaces, and local skills applicable to evidence, context, artifacts, security, or physics.

Fetch `origin`, compare local target and candidate ancestry with `origin/<default branch>`, and inspect PR state when relevant.

## Required output

Provide:

1. a fact table: confirmed, observed-but-unverified, inferred, unknown;
2. package-to-code contradiction matrix;
3. remote-state result and consistency with consumer work-state authority;
4. comparison of scope, validation, source context, artifact persistence, and safeguards;
5. P0/P1/P2 findings with exact evidence citations; and
6. decision: choose, merge with boundaries, defer, archive, reconcile, or reject.

A candidate remains draft-only until the consumer's declared state authority explicitly activates it. Do not infer source schemas, units, availability, context, or performance without evidence.
