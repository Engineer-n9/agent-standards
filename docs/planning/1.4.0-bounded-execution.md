### 1. Material stop conditions

References: `.claude/agents/sprint-coder.md:14,26`; `.github/copilot-instructions.md:13` (conflict paragraph).

```diff
- Stop if a required field is absent ... or an assumption is unverified.
+ Stop when missing information or uncertainty affects authorization,
+ safety, domain correctness, acceptance criteria or approved scope.
+ For non-material administrative omissions, record "not applicable"
+ with a brief reason and continue within the approved contract.
+ Never invent approval, acceptance requirements or external-data facts.
```

Wrapper conflict handling:

```diff
- If the local authority, packet, current code, external-system evidence,
- or standards adapter conflicts, stop and report the conflict.
+ Apply explicit authority precedence where it resolves the discrepancy.
+ Report stale lower-priority text without treating it as new authority.
+ Stop when the discrepancy remains unresolved and materially affects
+ authorization, safety, scope or acceptance.
+ A difference between code and requirements may be the defect being fixed;
+ it is not automatically an instruction conflict.
```

Administrative treatment cannot excuse an unstated dependency, forbidden path, changed contract or external-data uncertainty affecting correctness. No new authority precedence is invented.

### 2. Impact-based dependency mapping

Reference: `.claude/agents/sprint-architect.md:44`.

```diff
- If more than three implementation files are proposed, require a dependency map ...
+ Require a dependency map when work changes shared contracts, persisted formats,
+ domain semantics, external-data access or multiple independently owned surfaces.
+ File count alone does not trigger escalation.
+ For localized changes, name the canonical owner and affected consumers briefly.
+ All work still requires an approved scope.
```

This replaces the shared three-file trigger; it is not an additional opt-in mapping mode. Stronger explicit consumer controls are not overwritten.
